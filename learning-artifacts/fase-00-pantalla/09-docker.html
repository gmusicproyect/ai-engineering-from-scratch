Docker para IA

El contenedor hace que «en mi máquina funciona» deje de ser una excusa.

El problema

Entrenas con PyTorch 2.3, CUDA 12.4 y Python 3.12. Otra persona tiene PyTorch 2.1, CUDA 11.8 y Python 3.10. El modelo cae. Una imagen de Docker lleva el mismo conjunto a las dos máquinas.

La idea

Docker mete el código, el intérprete, las librerías y las herramientas en un contenedor. Comparte el núcleo del sistema, así que arranca en segundos, no como una máquina virtual completa.

PalabraQué es
ImagenLa plantilla de solo lectura. La receta, escrita en un Dockerfile.
ContenedorUna imagen en marcha.
VolumenDisco que sobrevive aunque el contenedor se borre. Ahí van modelos y datos.
ComposeVarios contenedores descritos en un YAML y levantados con un comando.

En IA hay tres formas habituales. El contenedor de desarrollo trae editor, Jupyter y depurador. El de entrenamiento es mínimo y corre en la GPU. El de inferencia es pequeño y arranca rápido para servir el modelo.

El toolkit de NVIDIA deja ver la GPU de la máquina desde dentro del contenedor. El toolkit de CUDA puede ir dentro de la imagen; el driver se queda en el anfitrión. Un modelo de 7 mil millones de parámetros pesa unos 14 GB en fp16: el volumen evita descargarlo en cada reconstrucción.

En esta Mac

Docker se instala con brew install --cask docker y se abre Docker.app. No hay GPU NVIDIA, así que un contenedor de entrenamiento con CUDA no usa Metal. Sirve igual para empaquetar el entorno de CPU y para los servicios que vienen más adelante.
