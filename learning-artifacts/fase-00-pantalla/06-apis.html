APIs y claves

Toda API de IA hace lo mismo: mandas un pedido y recibes una respuesta. Cambian los detalles, no el patrón.

El problema

Desde la fase 11 vas a llamar APIs de modelos de lenguaje. En las fases 13 a 16 los agentes las llaman en bucle. Hay que saber guardar la clave y hacer la primera llamada.

La idea

Cada llamada tiene cuatro piezas: una dirección (el endpoint), una clave, un cuerpo con lo que pides, y un cuerpo con lo que vuelve, casi siempre JSON.

La clave no va en el código. Vive en una variable de entorno o en un archivo .env que Git ignora. El programa solo nombra la variable. El valor entra al proceso al ejecutarlo y sale en la cabecera de autorización.

export ANTHROPIC_API_KEY="sk-ant-..."

El archivo .env lleva la misma línea, y .gitignore incluye .env.

La llamada

El SDK de Anthropic lee la clave del entorno. El modelo sale de LLM_MODEL; si no está, usa el alias de Sonnet.

import os
import anthropic

cliente = anthropic.Anthropic()
modelo = os.environ.get("LLM_MODEL", "claude-sonnet-5")
respuesta = cliente.messages.create(
    model=modelo,
    max_tokens=256,
    messages=[{"role": "user", "content": "¿Qué es una red neuronal, en una frase?"}],
)
print(respuesta.content[0].text)

Sin SDK, el mismo pedido es un POST a https://api.anthropic.com/v1/messages con la cabecera x-api-key. El SDK hace eso por dentro. Ver el HTTP crudo sirve para depurar.
