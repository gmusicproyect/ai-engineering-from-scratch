Git y colaboración

Sin historial vas a perder trabajo. Cada experimento de este curso se guarda.

El problema

Vas a escribir cientos de archivos en 20 fases. Sin control de versiones no puedes deshacer un cambio, ni ver cómo creció el proyecto, ni trabajar con otra persona.

Git es la herramienta. GitHub es donde vive el código. Esta lección cubre lo que hace falta para el curso.

La idea

El cambio pasa por cuatro sitios, en este orden:

  1. Directorio de trabajo: los archivos que editas.
  2. Área de preparación: lo que eliges guardar, con git add.
  3. Repositorio local: la foto del cambio, con git commit.
  4. Remoto, en GitHub: la copia de respaldo, con git push.

Tres hábitos: guarda a menudo, empuja al remoto, y abre una rama cuando el cambio es un experimento.

Hazlo

Identidad, una sola vez:

git config --global user.name "Tu nombre"
git config --global user.email "tu@correo.com"

El día a día:

git status
git add archivo.py
git commit -m "Agrega la implementación del perceptrón"
git push origin main

Una rama para probar sin romper la línea principal:

git checkout -b experimento/nuevo-optimizador
git checkout main
git merge experimento/nuevo-optimizador

Este repositorio del curso no acepta tus envíos directos. En GitHub se hace un fork, se clona esa copia y el progreso va en una rama propia:

git checkout -b mi-progreso
git push origin mi-progreso

Los comandos que alcanzan

ComandoCuándo
git cloneTraer el repositorio
git add y git commitGuardar el trabajo
git pushRespaldarlo en GitHub
git checkout -bProbar sin tocar main
git log --onelineVer qué se ha hecho

Para este curso no hacen falta rebase, cherry-pick ni submódulos. Un .gitignore debe dejar fuera los pesos grandes: *.pt, *.pth, *.safetensors.
